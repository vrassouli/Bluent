# Bluent v3 — initial consumer migration-impact ledger for Penpot #419

**Draft risk ledger, not an approved migration instruction.** Prepared from the existing Bluent 2.x source and the verified Penpot design/library research on 2026-10-11. It documents **potential** consumer impact for later #424 migration planning and component-specific issues. **No runtime component API, CSS, public package or stable v2 feature was changed under #419.**

## Non-breaking default proposal

1. **No stable package change is approved by a Penpot design file.** Keep the existing `ButtonAppearance.Default` and `Danger`, all old enum values, parameter binding semantics, DOM behavior and source client layout until a later component issue proves a safe replacement.
2. Use an **explicit compatibility alias map**, not direct consumer rename: Penpot `Secondary` **corresponds conceptually** to Bluent `Default`; both labels must remain traceable and visibly documented.
3. New design-only states and token names should be treated as proposals, **not** new public parameters. If a future PR does add an API, it must be an approved versioned change with examples, deprecation path, tests and full demo.
4. Migration guide #424 must include: upgrade order, CSS bundle/token precedence and Bootstrap utility preservation, before/after Razor, feature-specific fallback or adapters, keyboard/RTL/forced-colors test checklist and package compatibility matrix.
5. Owner of each runtime change is that component's **Ready → In progress** issue. #419 produces source-linked visual designs/handoff evidence and this ledger only.

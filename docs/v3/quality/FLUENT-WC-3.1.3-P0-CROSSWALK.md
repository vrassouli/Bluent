**Reference definition:** published tag, attribute, slot, event and CSS-part presence in `custom-elements.json` proves only that the release *declares* them. It does **not** prove that Bluent behavior/appearance matches those APIs, all possible Fluent releases lack a counterpart, or that a browser, screen reader, Penpot frame or stakeholder approved an implementation. ## Reproduction

1. In an isolated scratch directory, `npm pack @fluentui/web-components@3.1.3`. Verify NPM-provided `dist.integrity` against the string above.
2. Extract `custom-elements.json` and run `python scripts/quality/check_v3_fluent_wc_manifest.py --manifest PATH_TO_EXTRACTED_CUSTOM_ELEMENTS_JSON` to compare against this reviewed snapshot (without overwriting it).
3. To refresh a manifest after intentional package upgrade, obtain a new reviewed version/integrity + source, update the script and use `--write` only with reviewer approval. **Never silently upgrade** the pinned source or mark `parityAccepted=true`.
4. For a browser baseline, `scripts/quality/fixtures/fluent-wc-3.1.3-reference.html` and `fluent-wc-3.1.3-entry.js` are isolated specimen sources using **real registered WC elements**, not manually redrawn lookalikes. The reference builds with `@fluentui/web-components@3.1.3`, `@fluentui/tokens@1.0.0-alpha.24` and an isolated bundler. Screenshot, computed styles and keyboard outcomes only count once the actual browser probe succeeds and produces linked evidence; an attempted run or source-based fixture is not a visual PASS.

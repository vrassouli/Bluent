## #442/#443 actual browser PointerEvent coordinate audit — 2026-10-19

[Real WASM and published Production InteractiveServer Chrome pointer/scroll evidence](FLUENT-PARITY-P0-POINTER-SCREEN-VIEWPORT.md) confirms **ScreenX is 18px greater than ClientX**, whereas source subtracts viewport-relative `getBoundingClientRect().left`. Actual displayed values in all eight click/drag samples match the ScreenX formula, and differ by ~4–6 numeric units from a consistent clientX/rect formula. Both controls actually handled mouse callbacks in both modes in this smoke; do **not** claim the previously reported separate Server failure is universally present or universally resolved. App scroller differs (WASM nested `.page-content`, Server window) and is now captured correctly. Product coordinate and keyboard fixes remain issue-owner tasks #442/#443, without parity signoff.

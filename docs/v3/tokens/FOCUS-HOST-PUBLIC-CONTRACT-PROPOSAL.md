# #418 — Public Focus host-context contract proposal

**Status: DRAFT — maintainer decision required.** This document separates an already accepted visual direction from the still-open consumer API contract. It does not approve a new Razor parameter, wrapper component, public HTML attribute, CSS token name, production selector, or universal accessibility claim.

## 1. Decisions already settled — do not reopen

The maintainer accepted the Button's brand-colored Focus direction and TextField's underline-only Focus treatment. The ring geometry remains a 2px outline with a 2px offset.

The approved source-owned design is Bluent v3 Design System, page 38, board f4136a9a-101d-8004-8008-ca2956fe05f9. The corresponding host-role crosswalk is FOCUS-HOST-TOKEN-CROSSWALK.md.

The source audit covers ten actual emitted brands × Light/Dark × five opaque host roles = 100 source combinations. The generated explicit-only preview rejects any pair below 3:1. The mapping is measured against the OUTER host, not the Button face. The design decision is accepted; its consumer-facing annotation/fallback API is not.

## 2. Why host identity must be explicit

A Focus ring is painted outside the Button face. Its contrast therefore depends on the surrounding painted host surface. The source audit proved that no single role is valid for all hosts:

- The selected same-hue ring passes the neutral opaque host matrix.
- Brand, BrandHover and Danger filled hosts use the existing inverse foreground role.
- The Inverted host needs a mode-specific mapping; a universal white/inverse ring fails on Dark inverted white surfaces.
- The existing alpha-host audit found 10/80 Light alpha-on-brand combinations where BOTH approved opaque-host choices miss 3:1. The existing colorStrokeFocus2 black/white candidate passes the 80 analytic alpha cases, but remains research-only and is not a substitute for accepted design or real pixel/native testing.

Do not infer host kind from Button Appearance, computed pixels, ancestor color, screenshots, gradients or image sampling. A Button's own face does not identify the surface behind its outer ring. Nested theme roots must not be introduced just to select Focus mode; doing so can reinitialize global Fluent source variables and break inherited brand scopes.

## 3. Consumer-contract options

| Option | Shape | Benefit | Cost / risk |
|---|---|---|---|
| A — explicit same-host attributes (recommended proposal) | The actual painted host carries data-bui-v3-focus-mode and data-bui-v3-focus-host together. | Lowest API weight; matches the existing opt-in preview; host identity stays with the painted element. | Consumers must annotate each host and keep the mode/role synchronized with their own theme/brand state. |
| B — public scoped wrapper | A FocusHost / FocusScope wrapper cascades explicit kind and mode. | Can centralize repeated markup and nested scope declaration. | Adds public component lifecycle, nesting and cascade semantics. A wrapper may not be the actual painted ancestor; portal boundaries and DOM parity still need a defined contract. |
| C — no custom-host declaration | No public attributes/component; only existing named product hosts are supported. | Smallest public surface and no new consumer API. | Arbitrary application cards/containers cannot declare their real host kind; custom filled hosts receive no v3 host-contrast guarantee. |

**Recommendation to review, not an approval:** Option A. It changes the least surface area and matches the source evidence already generated by the v3 preview. Do not ship it as a public contract until the maintainer selects an option and accepts exact spelling, ownership, nesting and fallback semantics.

## 4. Existing preview contract — not yet public API

The current opt-in preview expects:

- An ancestor opt-in root marked data-bui-v3-tokens.
- data-bui-v3-focus-mode="light" or "dark" and data-bui-v3-focus-host on the SAME actual host element.
- Supported opaque host values only: neutral, brand, brandHover, danger, inverted.
- No product data-bui-theme attribute on every nested host; the focus-only mode avoids reinitializing global Fluent theme variables.
- The generated --bui-v3-focus-host-ring-candidate remains a candidate alias. It does not set outline-color, target the Button selector or alter the released 2.x assets.
- Under forced-colors: active, the preview uses the system Highlight color. Browser emulation is not native Windows Contrast Themes acceptance.

Outside the explicit v3 opt-in scope the candidate property is absent. None of these preview names or attributes are approved public HTML/CSS API.

## 5. Unsupported surfaces and fail-closed behavior

| Surface/context | Evidence and current boundary |
|---|---|
| Translucent / alpha-composited host | 80 analytic compositions; 10 Light alpha-over-brand cases fail 3:1 for both approved opaque ring choices. Focus2 candidate is research-only. |
| Gradient, image, video, shadow/composited host | No single opaque source role represents the visible painted background. |
| Nested/overlapping surfaces and portals | Parent token scope and actual painted host may diverge; lifecycle/ownership arbitration is not accepted by this proposal. |
| Hover / pressed / selected host state | Do not substitute an unrelated state role for Neutral/Rest. Define explicit state semantics only after source and design review. |
| Unknown host kind or absent opt-in metadata | Emit no new host-specific alias and do not infer contrast from pixels. Keep existing visible keyboard-focus behavior unchanged; do not claim a v3 host contrast guarantee for unsupported surfaces. |

Fail-closed means the preview does not fabricate a host-specific contrast value. It must NOT mean hiding or suppressing the existing keyboard focus indicator.

## 2026-11-16 decision — Option A selected

The maintainer delegated this choice to the engineering/design review. **Option A is selected as the future v3 contract direction**: use `data-bui-v3-focus-mode` and `data-bui-v3-focus-host` together on the actual painted host. Do not add a wrapper component or a Button Razor parameter. Do not infer host type from pixels.

For missing metadata or unsupported/translucent/gradient/image/composited hosts, do not emit a host-specific alias and preserve the existing visible keyboard-focus indicator without claiming a host-specific contrast guarantee. This is not production API/CSS approval: the current preview remains opt-in and the page-53 design board and native acceptance gates remain open.
